# 两分钟经验记录模板

> 这份模板是给“当时没空总结，但怕以后忘记”的时候用的。复制一份，填得不完整也没关系。

## 基础信息

- **标题**：例如「Agent 改完前端后，原来的按钮不见了」
- **日期**：
- **工具/模型/版本**：不知道就写“不清楚”
- **系统/环境**：例如 Windows、macOS、浏览器、Git 仓库

## 发生了什么？

**我本来想让 AI 做什么？**

（一句话）

**它实际做了什么？**

（能观察到的情况，不要先猜原因）

**最直接的证据是什么？**

（错误消息、终端输出、截图、提交 SHA、变更文件列表；注意脱敏）

## 我试过什么？

| 尝试 | 结果 | 证据 |
| --- | --- | --- |
| 第一次操作 | 成功 / 失败 / 不确定 | |
| 第二次操作 | 成功 / 失败 / 不确定 | |

## 目前状态

- [ ] 已解决，有证据
- [ ] 有临时绕过方案
- [ ] 尚未解决
- [ ] 无法复现

**我目前的解释（允许猜测，但标清楚）**：

**下次怎么避免**：

**还有什么待核实**：

## 可以直接发给 AI 的整理指令

```text
下面是我随手记录的一次 AI/Agent 使用问题。
请帮我整理成适合公开 GitHub 知识库的经验文章。

要求：
1. 把「可观察事实」「我的推测」「你的分析」分开。
2. 不要编造缺失的命令、版本、报错或解决结果。
3. 说明哪些地方需要补充截图、日志或提交 SHA。
4. 给出新手能懂的原因解释，以及可以复现/排查的步骤。
5. 检查是否包含密钥、Token、隐私和不适宜公开的内容；
   不要在输出中重复敏感原文。
6. 最后保留一个「尚未确认」小节。

原始记录：
【粘贴文字】
```

**建议习惯**：一出问题就保存报错原文和当时的 Git 提交 SHA；解决后再补一句最终处理方式。比事后凭记忆复述可靠得多。
