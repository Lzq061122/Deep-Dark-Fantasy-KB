# Agent Experience Lab｜通用经验提炼与积累

> 维护：AdenineLeo（Ade）  
> 状态：V0 已建立私有经验库，收录首批 5 条经验（2026-10-26）  
> **不是面向新手的教程生产线，也不以公开发布为目标。**

## 为什么做？

我在不同 AI Agent、Harness 与真实软件项目中留下了提交、测试记录、设计决策、故障与解决过程。很多实用判断不应该散落在某个聊天窗口或者只凭记忆保存。

这个项目的目的，是把其中**有代表性、可迁移、值得日后再次采用或警惕的经验**整理成一个持续增长的知识库。即使经验涉及较复杂的工程机制、不是“初学者一看就懂”，只要有复用价值，就可以收录。

## 两套系统，各司其职

| 项目 | 用途 |
| --- | --- |
| **PAIPOS Lite** | 让 Agent 在以后的任务中依照确认过的规则工作，管理角色、偏好、Skills 和经验候选 |
| **Agent Experience Lab** | 沉淀**可供人理解、引用和复用**的技术判断、故障机制、工程策略、反例和设计取舍 |

两者可以交流经授权的来源线索，但不自动复制私人记忆，也不自动把经验变为 PAIPOS 正式规则。

## 什么经验值得存？

一个条目至少说明：

- **结论**：遇到某类问题，值得采取什么判断或做法？
- **触发条件**：在哪些情况下适用？
- **机制与方法**：为什么成立，如何操作或排查？
- **代表案例**：最初从哪个真实任务中发现？
- **来源和确定性**：具体证据在哪里；哪些已核查，哪些尚未验证？
- **适用边界**：有哪些反例、成本和不能套用的场景？

关注**代表性、复用性和可靠追溯**；没有规定字数、篇数、读者基础或教学时长。遇到值得收录但暂时证据不完整的内容，可以先标为 `待核实` 入库，日后补证。

## 最小流程

```text
指定一个授权工作区
  → 只读查看文档、Git 记录和已有测试证据
  → 提炼代表性经验
  → 在经验库查重、合并相似记录
  → 生成精简条目，写入私有经验库
  → 日后随工程实践补证或纠正
```

**不需要先写一篇文章再入库，更不要求审核一篇文章后才能保存。** 使用本地 Agent 时，允许在已授权的私有库内边发现、边保存，带证据状态即可；不能因此自动发布到公开仓库。

## 现在有什么？

首轮从 CultureLens 工程记录中整理出五条可复用主题：

1. 验收结论必须绑定证据与适用范围；
2. 模型输出是不可信的外部输入；
3. 空值不等于没有用户意图；
4. 文件校验和应基于最终字节；
5. 操作成功不代表目标状态生效。

上述条目已存入独立的**私有 GitHub 经验库**。原始调查报告、审查请求仍保留作历史依据。部分细节尚未独立复跑，不能把经验条目本身当作验收报告。

本页在公开仓库中只提供项目说明，**不复制私有经验正文、候选报告或来源索引**。以后如果想和 Ethan 分享某条经验，再单独决定是否摘录；这不是本项目的必经环节。
