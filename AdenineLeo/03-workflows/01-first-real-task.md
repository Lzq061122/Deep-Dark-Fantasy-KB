# 第一次实战：让 AI 帮你整理一篇真正能分享的教程

这篇不需要会编程，只需要能打开 AI 聊天框和一个文本编辑器。

**目标**：在 20～30 分钟内，做出一篇给朋友看的《如何防止手机照片丢失》入门文章。它应当有清晰步骤、风险提示和可执行的检查清单。

## 0. 先决定什么算“完成”

在打开 AI 之前，写下验收标准：

- 新手能看懂，不需要技术基础。
- 有 3～5 个可以逐条执行的步骤。
- 区分“已经备份”和“只是开启某个开关”。
- 不凭空编造手机系统的按钮名称。
- 读完能亲自确认至少有一份可恢复的备份。

如果你没有标准，AI 可能交出一篇很好看、但实际用不了的文章。

## 1. 第一轮：让它先做提纲

```text
我要写一篇给完全不懂技术的朋友看的教程，主题是
《如何防止手机照片丢失》。

目标：读者知道为什么需要备份，并能自己做一份备份。
长度：约 600～900 字。
限制：不假设具体手机品牌、系统版本；不编造按钮名称。
请先给出文章结构，并说明你还需要确认哪些情况。
先不要写正文。
```

看提纲有没有重要遗漏。你可能发现需要区分 Android、iPhone、电脑、云存储，这时告诉 AI 哪些要写、哪些暂时不写。

## 2. 第二轮：生成正文，但保留不确定性

```text
按刚才的提纲写成面向新手的教程。
涉及具体系统菜单的位置时，如果不能确定，请写成
“以当前设备界面为准”，不要猜按钮名称。
每一步都说明“完成后应该看到什么结果”。
最后给出一个简短的检查清单。
```

**不要直接转发。** 先看是否有错误、过时步骤或夸大保证。

## 3. 第三轮：把 AI 当作审稿助手

```text
请审查这份教程，列出：
1. 哪些句子没有给出依据？
2. 哪些步骤会因不同设备而变化？
3. 哪些表述可能让新手误解？
4. 哪些操作涉及隐私或不可逆风险？

只修改有问题的地方，说明修改原因。
```

这次审查可能仍有遗漏。**应由你实际操作验证**关键步骤，特别是“能否恢复照片”。

## 4. 第四轮：交付和保存

把最终内容保存成 Markdown 或普通文本文件。标注日期、适用范围；如果引用了资料，添加原始链接。

可以附一句：

> 本文描述通用思路。手机系统界面可能因品牌和版本不同而变化；请以实际设备和官方说明为准。

## 5. 复盘：这次到底学会了什么？

你没有使用复杂的提示词，也没有用到 Agent，但已经完成一次基本工作流：

```text
定义目标 → 约定完成标准 → 生成草稿
    → 发现问题 → 修订 → 人工验收 → 保存成果
```

以后写代码、做 PPT、写报告、整理课程笔记，也能沿用这条主线。

**进阶**：当某项任务确实要操作多个文件、搜索或运行程序时，再考虑让有权限的 Agent 执行。其中最不能省的步骤，仍然是验收。
