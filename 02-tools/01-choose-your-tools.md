# AI 工具怎么选？先看任务，再看模型

刚入门时，最大的诱惑是：看见一个新 AI 工具，就想立刻安装。但很多工具解决的是不同问题，不必全装。

## 先按任务选工具类型

| 我现在要做什么？ | 先找哪类工具？ | 你需要关注什么？ |
| --- | --- | --- |
| 问问题、看懂课程、整理思路 | AI 聊天产品 | 是否容易追问、解释是否清楚 |
| 总结文档或整理资料 | 带文件处理能力的 AI 产品 | 是否实际读取文件、引用能否回查 |
| 写一小段代码或排查报错 | 聊天助手或编辑器内的 AI | 能否看到完整错误、能否解释修改 |
| 在项目里改多个文件并运行测试 | Coding Agent（编程智能体） | 文件权限、终端能力、修改记录与测试 |
| 把多个步骤串成自动化流程 | Agent / 自动化工具 | 权限边界、失败重试、日志与人工确认 |

## 常见名字分别属于哪一类？

这里仅介绍**工具定位**，不提供动态榜单：

- **ChatGPT**：面向广泛任务的 AI 产品。常见用途包括讨论问题、学习、写作、研究与处理材料；具体可用功能取决于平台和账户。
- **Codex**：面向软件开发任务的编程 Agent 产品/能力，常用于理解代码、修改项目和执行工程工作。
- **OpenCode**：面向编程工作流的开源 Agent 工具。可以关注它怎样连接模型、管理项目上下文、修改代码。
- **Hermes Agent**：侧重 Agent 工作方式的工具。评价它时应看你实际安装的版本提供哪些执行和管理能力。
- **DeepSeek Harness**：偏向 Agent 运行环境与编排的工具。更适合已经想研究执行流程、模型接入和任务机制的人。

**重要**：这些东西并不全是同一层级的产品。把“模型”“软件界面”“Agent 框架”放在同一个排行榜里，结论通常意义不大。

## 新手推荐的顺序

**阶段 A：先用一个聊天产品。** 练习提问、改写、总结、核对事实。

**阶段 B：有真实编程需求，再试一个 Coding Agent。** 在小型测试项目中使用，先学会查看 diff、运行测试、撤销修改。

**阶段 C：只有在遇到明确限制时，再研究 MCP、Skills、Harness。** 比如你确实需要接入外部工具、复用一套固定流程，或管理复杂的工程任务。

## 付费前问自己的五个问题

1. 我每周究竟有多少次需要它？
2. 免费版本是否已经能完成主要任务？
3. 它是订阅收费，还是 API 按使用量收费？有没有双重计费的可能？
4. 它能导出成果、查看日志或备份数据吗？
5. 如果明天不用它，我的工作能否继续？

价格、额度、地区可用性和产品能力会变，所以这篇故意不写死某个套餐“最划算”。

## 一个常见误区：同一个模型，为什么换软件感觉不一样？

因为最终结果也取决于：
- **上下文**：AI 实际读到了哪些文件和对话？
- **工具**：它可以搜索、改文件、运行命令吗？
- **权限**：系统允许它做什么？
- **工作流**：它会不会规划、检查、重试？
- **评价方式**：你是凭一句回答判断，还是用实际任务测试？

**一句话建议：** 先把一个工具用到能稳定解决你的问题，再考虑增加第二个。
