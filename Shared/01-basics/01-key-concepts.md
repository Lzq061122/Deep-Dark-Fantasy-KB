# 一次搞懂：模型、AI 产品、Agent、工具、MCP、Skill

**目标**：读完这篇，至少能回答「ChatGPT 和 GPT 是同一个东西吗？」以及「为什么 Agent 能改文件，普通聊天却不一定能？」

## 先看一张表

| 名词 | 你可以怎样理解 | 一个例子 |
| --- | --- | --- |
| **大语言模型（LLM）** | 负责理解输入、生成输出的模型 | GPT 系列、DeepSeek 系列等 |
| **AI 产品 / 客户端** | 你实际打开和使用的界面、功能和服务 | ChatGPT 网页或 App |
| **Agent（智能体）** | 以目标为导向，循环调用工具、观察结果并继续行动的系统 | 能读代码、修改文件、运行测试的编程 Agent |
| **工具（Tool）** | Agent 获准调用的一项具体能力 | 搜索文件、执行命令、访问日历 |
| **MCP** | 一种让 AI 应用连接工具和数据源的开放协议 | 应用借助 MCP 接入外部服务 |
| **Skill** | 通常是给 Agent 使用的一套任务说明、规则和资源；具体实现因产品而异 | “做代码审查时按此流程检查”的技能 |
| **Harness（运行环境/编排层）** | 负责管理模型调用、工具执行、上下文、权限与任务流程的软件体系 | 一个为编程 Agent 提供执行环境的框架 |

这张表是入门近似理解，并非所有产品都采用完全一致的术语。

## 1. 模型与产品：像发动机与整辆车

你打开 ChatGPT，看到的不只是一个“模型”。

一个 AI 产品可能还包括聊天界面、搜索、文件处理、项目空间、语音、账户权限等。模型负责其中一部分智能处理；**产品功能并不等于模型本身的能力**。

所以：
- “我用了某个模型”通常在说背后的推理/生成引擎。
- “我用了某个 AI 软件”通常在说整个使用体验。
- 同一个模型接到不同软件中，能调用的工具、能拿到的上下文和最终表现可能不同。

## 2. 普通聊天和 Agent：差在“做事的闭环”

普通聊天的典型过程：

```text
你提问 → 模型回答 → 你自己去做
```

有工具权限的 Agent 可能这样工作：

```text
你提出目标
  ↓
Agent 判断下一步
  ↓
读取文件 / 搜索 / 修改代码 / 运行测试
  ↓
观察结果（成功了？报错了？）
  ↓
必要时重试或调整
  ↓
交付结果和证据
```

这里的“自主”是**在授权范围内**完成多个步骤，不等于它拥有无限权限，也不等于它会做出正确决策。

例如你让 AI 帮你写网页：
- 仅聊天：AI 给你一段代码，需要你复制。
- 编程 Agent：如果已经授权它访问项目，它可能直接修改代码文件，并运行测试。

## 3. MCP 和 Skill 解决不同的问题

一个容易记住的方式：

- **Tool** 是具体按钮：比如“读取这个文件”。
- **MCP** 像连接规范：不同应用可以按统一约定接入外部工具和数据源。
- **Skill** 像工作手册：告诉 Agent 遇到某类任务，应当按照什么方法操作和检查。

它们可以配合，也可以分别出现。Skill 本身不保证 Agent 获得新的系统权限。

## 4. 什么是 Harness？为什么你可能暂时不需要懂它？

模型会生成下一步建议，但谁把这些建议变成真实的工具调用？谁保存上下文、限制权限、记录日志、安排步骤？

这部分通常由应用或 Agent 运行环境负责。很多人用 **Harness** 指这一层工程系统。

因此选择 Agent 时，别只问“背后用了哪个模型”，也要看：
- 有没有你需要的工具？
- 是否容易看清它做了什么？
- 能不能限制权限和撤销修改？
- 失败时可不可以恢复并继续？

新手阶段不用先搭自己的 Harness。先体验现成产品，再根据真实需要探索。

## 5. 你现在应该记住什么？

**模型决定一部分智能能力，产品决定交互体验，Agent 决定任务是否能形成执行闭环，工具和权限决定实际能做的事。**
