# E-07｜区分 Agent 命名与正式状态

**领域**：Agent 协作 / 项目沟通  
**来源**：2026-10-27 项目协作中的命名歧义，经授权概括  
**证据等级**：本次核对了相关独立审查记录；通用做法是实践建议，尚无采用前后的对照数据。

## 可复用结论

Agent 自取的代号、分支名、探针名和专有术语，需要说清含义与适用范围。名称中出现的阶段、功能或状态字样，不能作为正式进度、授权或验收通过的证据。

## 触发场景

多个 Agent 或团队协作时，临时名称可能沿着分支、文件、派单和交接材料传播；如果同一个词同时用于实验名称和正式阶段，就容易造成误判。

## 做法

- 对易误解或需要跨会话使用的名称，维护轻量术语表：名称、所属项目、类别、含义、易混淆项、来源与核对时间。
- 首次向用户提及时直接解释；若名称看起来像正式阶段或功能，说明两者的区别。
- 判断进度、授权和验收时查相应正式记录与证据。来源不明就标注待核实，不猜测命名者的意图。
- 保留旧名的解释；状态改变时更新条目，注明核对时间。

## 代表案例

一次项目中，实验分支名称包含阶段编号；独立审查指出它只是探针命名，并不代表该阶段已正式解锁。单看分支名会误判进度，需要分别核实名称含义和阶段状态。

## 边界

不要求登记每个显而易见的临时变量或一次性文件，也不增加审批流程。术语表是否被不同 Agent 读取，需要在各自实际工作区验证；文件存在或注册不等于实际加载，更不等于行为已经符合规范。
