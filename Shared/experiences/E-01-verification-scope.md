# E-01｜验收结论必须明确适用范围

**领域**：工程验收 / Agent 交接 / 证据管理  
**来源项目**：CultureLens · Ade  
**核查状态**：已对照公开的范围约定与验收记录；未进行效果对照试验。

## 可复用结论

不要只说“通过”，而应同时写出**完成了什么、依据是什么、在哪些条件下成立**。一项测试成功不自动扩大到未检查的版本、环境、规模或真实效果。

## 触发场景

- Mock 或模拟服务通过了检查，但真实 API 尚未打通。
- 小规模样本测试通过，却准备对大型数据集作出结论。
- 多个 Agent 或不同开发者之间交接阶段成果。
- 需要评价“功能已实现”“单测通过”“端到端验证”是否等价。

## 操作原则

以“**断言｜证据｜范围**”记录结论，至少保留被测版本、输入规模、环境以及未覆盖项。没有执行的检查写“未验证”，不要用推测补足。

## 代表案例

CultureLens D0 在项目范围中明确：网络/API 阻塞时可继续开发 Mock UI，但不得据此宣称真实 AI 链路完成。最终验收又把 Windows 同机、六段合成字幕与尚未进行的异机、长字幕和独立翻译质量验证区分开。

## 边界

这是一条报告质量原则，**不意味着采用该原则一定能量化减少返工**；对极小、确定性的本地改动可使用更简短的验收记录。
