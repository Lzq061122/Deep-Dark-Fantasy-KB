# E-02｜把模型输出视为不可信的外部输入

**领域**：LLM 集成 / 数据验证 / 数据库一致性  
**来源项目**：CultureLens · Ade  
**核查状态**：公开的校验代码、历史缺陷报告及事务实现已对照；未重新运行全套测试。

## 可复用结论

模型返回合法 JSON，不代表它符合业务契约。**解析、结构验证、业务语义验证、持久化**是不同的步骤。必须在产生副作用前检查完整数据；需要整体一致的写入应由事务保证。

## 触发场景

- AI 输出结构化对象并写入数据库或文件。
- 模型返回对象 ID、关联关系、状态变更或批量操作。
- 一次请求中含多项动作，部分成功可能破坏一致性。

## 操作原则

1. 先判断是不是可解析的数据，再校验字段、类型、取值范围。
2. 对 ID 做存在性、重复性与关联约束校验。
3. 先验证**整批**请求，之后才写入需要保持一致的数据。
4. 对同一事务中的成功和失败路径进行测试。
5. 重试应考虑错误类别、幂等性和副作用；“重试一次”并不是通用规则。

## 代表案例

CultureLens 的字幕处理要求模型输出 ID 与原有字幕段对应。历史集成审查发现：一个审核请求里前一个建议动作成功、后一个建议 ID 不存在时，接口返回失败，但先前的建议状态已部分写入。修复思路是整批动作先验证，统一事务写入。

## 边界

对于只展示、不会改变持久状态的建议，可以根据风险选择不同强度的验证；但仍不能把“JSON 可解析”混同于“内容可信”。
