# 测试通过了，就能说“项目没问题”吗？

> 适合：AI 新手、刚开始用 Coding Agent 开发项目的朋友  
> 原始案例：CultureLens 的 2026-10-21 D0 集成验收  
> 证据：[公开验收报告](https://github.com/Lzq061122/CultureLens/blob/main/docs/CODEX_D0_FINAL_REVIEW.md) · [状态说明](https://github.com/Lzq061122/CultureLens/blob/main/docs/STATUS.md)

## 先说结论

**一份测试报告能够证明的，是它实际检查过的那些条件。**

比如一个网页在你自己的电脑上完成了三次操作流程，说明这些操作在当时的环境、数据和版本下通过了检查；它还不能自动说明一千人同时使用也没有问题。

这和考试有点像：你做对了三道题，当然是好消息，但还不能推断整张试卷都会做。

## 一个真实例子：CultureLens

CultureLens 是一个处理视频字幕本地化的项目。D0 阶段的任务可以概括为：

```text
导入中文 SRT
   → AI 生成英文字幕初稿及文化建议
   → 人工修改 / 采纳 / 忽略
   → 导出英文 SRT
```

它的公开验收记录写明：2026 年 10 月 21 日，D0 在 **Windows 同机隔离环境**通过了基础集成验收。其中，最终候选有 **46 项后端测试通过**，前端类型检查和构建通过，并完成 **3 次独立的网页端真实生成与导出闭环**。

这些是明确记录过的成果。

但报告同时明确，三次导出的样本均为 **6 段合成字幕**。这意味着验收尚未覆盖真实长视频、大量字幕、多用户并发、跨操作系统使用，也不意味着翻译质量已经经过独立评测。

所以，一个准确的表述是：

> D0 基础流程在报告规定的 Windows 隔离环境与测试样本中完成了验证；其他场景仍需后续测试。

如果只说“整个翻译平台都完美通过”，就超出了证据能够支持的范围。

## 怎样读一份 AI 或 Agent 交给你的测试报告？

最好找齐下面四个要素：

| 问题 | 具体要看什么 |
| --- | --- |
| **测试的是什么？** | 某个按钮、某条 API、完整业务流程，还是项目整体？ |
| **用的是什么环境？** | 系统、运行时、模型服务、代码版本、配置 |
| **用的是什么数据？** | 合成样本还是真实数据，规模有多大 |
| **还有什么没测？** | 并发、异常情况、兼容性、性能、实际效果 |

缺少其中一项，不一定说明测试不合格，但你应当谨慎解释结果。

## 一个初学者也能动手的练习

假设让 Agent 做了一个「待办事项」小网页：

1. 先检查添加、勾选和删除待办事项是否工作。
2. 刷新页面，看看数据是否保留；如果你的要求里没有持久化，就不要暗自假定有这个功能。
3. 测试输入空白任务、很长的文字，看界面是否处理得当。
4. 再让 Agent 列出它**没测**的情况，例如不同浏览器或手机屏幕。
5. 最后写一份只有五行的报告：测试版本、环境、数据、通过的项目、未验证的项目。

你会发现，“能不能用”开始变成一个有边界、能检查的问题。

## 给 Agent 的一个简短提示词

```text
请总结本次实际执行的测试结果。
分别列出：
- 测试对象、版本与环境
- 真实运行过的命令或操作
- 使用了哪些样本
- 有哪些客观结果可以核对
- 哪些场景尚未测试

只依据可检查的记录下结论；不要把“计划测试”当作“已测试”。
```

## 这一案例的适用边界

这篇从 **CultureLens 已公开的 D0 验收材料**中提炼了一个通用的验收习惯，并没有独立复跑 CultureLens 当前版本的所有测试，也没有对它的翻译质量做新测评。

后续项目代码可能变化，因此本文描述的是 **2026-10-21 的固定历史案例**，不是对项目在任意时间、任意平台上的持续保证。
